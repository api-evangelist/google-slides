<h3><span style="vertical-align: baseline;">GKE Agent Sandbox: Accelerating the agentic era</span></h3>
<p><span style="vertical-align: baseline;">As </span><span style="vertical-align: baseline;">AI evolves from simple conversational chatbots to entire ecosystems of proactive, autonomous agents, the underlying infrastructure must adapt to handle hundreds or thousands of agents collaborating with workers to plan, evaluate, and execute complex tasks. At scale, infrastructure performance, responsiveness, and rigorous security are essential. </span></p>
<p><span style="vertical-align: baseline;">We are excited to announce </span><a href="https://docs.cloud.google.com/kubernetes-engine/docs/concepts/machine-learning/agent-sandbox"><strong style="text-decoration: underline; vertical-align: baseline;">GKE Agent Sandbox</strong></a><span style="vertical-align: baseline;">, the industry’s most scalable and low-latency agent infrastructure. Built with gVisor kernel isolation — the same technology securing Gemini — Agent Sandbox allows you to safely execute untrusted code, tools, and entire agents without sacrificing performance. </span><span style="vertical-align: baseline;">GKE provides leading speed and efficiency for fully isolated agents with </span><strong style="vertical-align: baseline;">300 sandboxes per second at sub-second latency and up to 30% better price-performance when running on Axion compared to other hyperscale clouds.</strong></p>
<p><span style="vertical-align: baseline;">Lovable empowers anyone to build apps and websites — with builders creating 200,000+ new projects daily.  Lovable runs these AI-generated applications in GKE Agent Sandboxes because of the fast startup, fast scaling and secure isolation. </span></p>
<p style="padding-left: 40px;"><span style="font-style: italic; vertical-align: baseline;">GKE's cutting-edge sandboxing capabilities allow us to reliably scale to hundreds of secure sandboxes per second, ensuring we can seamlessly empower builders, even during massive, unpredictable demand." </span><span style="vertical-align: baseline;">- Fabian Hedin, Co-founder, Lovable </span></p>
<h3><span style="vertical-align: baseline;">GKE hypercluster redefines the scalability ceiling </span></h3>
<p><span style="vertical-align: baseline;">As foundational AI models grow exponentially and accelerators remain in high demand, organizations resort to fracturing Kubernetes compute infrastructure into hundreds of disconnected clusters, which can create a massive operational burden. To help, we’re announcing the private GA of </span><strong style="vertical-align: baseline;">GKE hypercluster</strong><span style="vertical-align: baseline;">, which allows a single, Kubernetes conformant GKE control plane to manage a million chips distributed across 256,000 nodes — spanning multiple Google Cloud regions. With the GKE hypercluster, widely distributed infrastructure becomes a single, unified capacity reserve that spans geographical locations.</span></p>
<p><span style="vertical-align: baseline;">To scale globally without compromising security, GKE hypercluster relies on Google’s Titanium Intelligence Enclave, a software-hardened security engine that delivers private AI compute. This "no-admin-access" model provides hardware-attested, pod-level isolation, so that proprietary model weights and prompts remain cryptographically sealed from platform administrators and infrastructure layers.</span></p>
<h3><span style="vertical-align: baseline;">Supercharging state-of-the-art inference</span></h3>
<p><span style="vertical-align: baseline;">Achieving frontier inference requires months of complex performance tuning. To reduce this heavy lifting, GKE now slashes your "time to SOTA" across TPUs and GPUs to mere minutes. We do this with new capabilities:</span></p>
<ul>
<li style="vertical-align: baseline;">
<p><span style="vertical-align: baseline;">ML-driven </span><a href="https://llm-d.ai/blog/predicted-latency-based-scheduling-for-llms" rel="noopener" target="_blank"><strong style="text-decoration: underline; vertical-align: baseline;">Predictive Latency Boost</strong></a><span style="vertical-align: baseline;"> in GKE Inference Gateway, which can reduce time-to-first-token latency by up 70% by replacing heuristic guesswork with real-time capacity-aware routing — no manual tuning required. </span></p>
</li>
<li style="vertical-align: baseline;">
<p><strong style="vertical-align: baseline;">Automatic KV Cache storage tiering</strong><span style="vertical-align: baseline;"> across RAM, Local SSD, and GCS/Lustre solves long-context memory bottlenecks. </span><a href="https://github.com/llm-d/llm-d/blob/main/guides/tiered-prefix-cache/README.md" rel="noopener" target="_blank"><span style="text-decoration: underline; vertical-align: baseline;">Offloading KV Cache</span></a><span style="vertical-align: baseline;"> to RAM yielded a more than 40% TTFT reduction and a 50% throughput gain for a 10K system prompt length. Offloading KV Cache to Local SSD yielded an almost 70% throughput improvement for a 50K system prompt length. Learn more about these benchmarks in the </span><a href="https://github.com/llm-d/llm-d/blob/main/guides/tiered-prefix-cache/storage/README.md#benchmarking" rel="noopener" target="_blank"><span style="text-decoration: underline; vertical-align: baseline;">llm-d Offloading Prefix Cache to Shared Storage guide</span></a><span style="vertical-align: baseline;">.</span></p>
</li>
</ul>
<p><span style="vertical-align: baseline;">Built as part of a layered composable suite, these new GKE capabilities leverage llm-d, now an official </span><a href="https://cloud.google.com/blog/products/containers-kubernetes/llm-d-officially-a-cncf-sandbox-project"><span style="text-decoration: underline; vertical-align: baseline;">CNCF Sandbox project</span></a><span style="vertical-align: baseline;">. To give you maximum flexibility, we’ve partnered closely with NVIDIA to seamlessly integrate Dynamo for scaling massive </span><a href="https://cloud.google.com/blog/products/compute/scaling-moe-inference-with-nvidia-dynamo-on-google-cloud-a4x?e=48754805"><span style="text-decoration: underline; vertical-align: baseline;">Mixture-of-Experts (MoE) models</span></a><span style="vertical-align: baseline;">. Whichever tools you choose, GKE provides the highly-optimized, flexible infrastructure you need to safely run any frontier AI workload — including the advanced agentic capabilities of the newly announced </span><a href="https://cloud.google.com/blog/products/ai-machine-learning/gemma-4-available-on-google-cloud?e=48754805"><span style="text-decoration: underline; vertical-align: baseline;">Gemma 4</span></a><span style="vertical-align: baseline;">.</span></p>
<h3><span style="vertical-align: baseline;">Eliminating RL compute bottlenecks</span></h3>
<p><span style="vertical-align: baseline;">Reinforcement learning (RL) is a key driver of AI compute demand and RL jobs involve sequential processing for sampling, reward, and training that can leave GPU and TPU accelerators idle between these RL steps. To streamline RL, we are adding new GKE capabilities in preview:</span></p>
<ul>
<li style="vertical-align: baseline;">
<p><a href="https://github.com/llm-d-incubation/py-inference-scheduler" rel="noopener" target="_blank"><strong style="text-decoration: underline; vertical-align: baseline;">RL Scheduler</strong></a><span style="vertical-align: baseline;"> solves for the "straggler effect" and inter-batch tail latency, maximizing throughput via intelligent routing.  </span></p>
</li>
<li style="vertical-align: baseline;">
<p><strong style="vertical-align: baseline;">RL Sandbox</strong><span style="vertical-align: baseline;"> provides kernel-level isolation for tool-calling and reward evaluation with millisecond-scale provisioning. Easy integration with RL sampling and reward steps.</span></p>
</li>
<li style="vertical-align: baseline;">
<p><a href="https://docs.cloud.google.com/kubernetes-engine/docs/tutorials/monitor-reinforcement-learning-workloads"><strong style="text-decoration: underline; vertical-align: baseline;">RL Observability and Reliability</strong></a><span style="vertical-align: baseline;"> dashboards offer the deep visibility required to troubleshoot and optimize the entire RL loop instantly, out of the box.</span></p>
</li>
</ul>
<p><span style="vertical-align: baseline;">Review the RL on GKE recipe, specifically the implementations for </span><a href="https://docs.cloud.google.com/kubernetes-engine/docs/tutorials/scaling-rl-verl-gke"><span style="text-decoration: underline; vertical-align: baseline;">Verl</span></a><span style="vertical-align: baseline;"> and </span><a href="https://docs.cloud.google.com/kubernetes-engine/docs/tutorials/nemo-rl-gke"><span style="text-decoration: underline; vertical-align: baseline;">NeMo RL</span></a><span style="vertical-align: baseline;">.</span></p>
<h3><span style="vertical-align: baseline;">Intent-based autoscaling on custom metrics</span></h3>
<p><span style="vertical-align: baseline;">Traditionally, scaling AI workloads based on application health has imposed a "custom metric tax." To scale the system on anything but basic compute or memory utilization, organizations have to manage complex monitoring systems and IAM roles. This creates operational risk: if your external observability stack fails, your autoscaling breaks along with it.</span></p>
<p><strong style="vertical-align: baseline;">Intent-based autoscaling</strong><span style="vertical-align: baseline;"> eliminates this overhead via native </span><a href="https://docs.cloud.google.com/kubernetes-engine/docs/how-to/expose-custom-metrics-autoscaling"><strong style="text-decoration: underline; vertical-align: baseline;">custom metrics support</strong></a><strong style="vertical-align: baseline;"> for GKE’s Horizontal Pod Autoscaler (HPA)</strong><span style="vertical-align: baseline;">. This agentless architecture bypasses external dependencies by sourcing metrics directly from Pods, hardening reliability while cutting costs. Crucially, it drops reaction times from 25 seconds to just 5 seconds—a </span><span style="vertical-align: baseline;">5x </span><span style="vertical-align: baseline;"> performance gain for near-instantaneous infrastructure elasticity.</span></p>
